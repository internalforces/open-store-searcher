# 데이터와 상태

> 대상: 검색 결과의 상태와 근거를 올바르게 해석하려는 사람
> 구현 입력: 아니오
> 기준 상태: M0 검토 완료 — 데이터 계약과 상세 매핑은 M1 조사 전
> 최종 검토일: 2026-08-24
> 상태: M0에서 본문 변경 없이 재검토했으며 구체적인 원천 계약은 미확정

## 어떤 데이터를 사용할 것인가

주 데이터는 지방행정 인허가 공개데이터다. 초기에는 서울특별시 소재 인허가 사업장을 대상으로 한다.

다만 현재는 정확한 다운로드 주소, 파일 형식, 인증 방식, 제공 필드, 이용조건과 출처표시 의무를 확인하기 전이다. M1에 들어가기 전에 공식 문서를 조사하고 사람의 승인을 받아 데이터 계약을 확정한다. 확인되지 않은 내용을 임의로 채우지 않는다.

## 화면에 표시할 네 가지 상태

| 표시 상태 | 의미 | 주의할 점 |
|---|---|---|
| `행정상 영업` | 공개 행정 데이터에 정상·영업 상태로 명확히 기록됨 | 지금 문이 열려 있거나 현장에서 실제 영업 중이라는 뜻이 아님 |
| `휴업` | 원본 상태 또는 제공된 휴업 정보가 명확한 휴업을 나타냄 | 실제 재개 여부가 데이터에 늦게 반영될 수 있음 |
| `폐업` | 원본 상태가 폐업으로 명확히 분류됨 | 출처와 데이터 기준일을 함께 확인해야 함 |
| `확인되지 않음` | 일치 결과 없음, 후보 충돌, 알 수 없는 상태 코드 또는 데이터 오류로 단정할 수 없음 | 다른 상태를 추측해 대신 표시하지 않음 |

화면에서는 이 네 가지 이외의 가공 상태를 만들지 않는다.

## 상태를 보여줄 때 함께 제공할 근거

가공된 상태 하나만 보여주면 사용자가 판단 과정을 확인할 수 없다. 따라서 결과에는 다음 정보를 함께 표시하는 것이 원칙이다.

- 원본 영업상태명과 상세영업상태명
- 가공된 네 가지 화면 상태
- 사업장명과 주소
- 업종 또는 업태
- 인허가일, 휴업 관련 날짜, 재개업일, 폐업일과 최종 수정일 중 제공되는 값
- 원본 데이터 출처
- 데이터 기준일

제공되지 않는 값은 숨기거나 빈 문자열로 오해하게 두지 않고 `정보 없음`으로 표시할 계획이다.

## 단정하지 않는 경우

### 검색 결과가 없음

공개데이터에 포함되지 않았거나 상호가 바뀌었거나 검색어 표기가 다를 수 있다. 따라서 결과가 없다는 이유로 `폐업`을 표시하지 않는다.

### 이름은 같지만 주소가 다름

동명이점이나 이전 사업장일 수 있다. 자동으로 하나를 확정하지 않고 주소가 다른 후보를 분리해 사람이 확인하도록 한다.

### 처음 보는 상태 코드

원천 데이터에 새로운 상태 코드가 생겨도 임의로 영업·휴업·폐업 중 하나에 넣지 않는다. 검증에서 변화를 감지하고, 매핑 규칙이 승인될 때까지 `확인되지 않음`으로 처리한다.

### 데이터가 잘못되거나 일부 필드가 없음

해당 레코드를 안전하게 제외하거나 상태를 확정하지 않는다. 오류 하나 때문에 전체 검색이 중단되지 않게 하는 방향으로 설계하되, 정확한 처리 방식은 데이터 계약과 테스트를 통해 확정한다.

## 데이터 기준일과 오래된 데이터

모든 결과에는 어떤 시점의 데이터를 사용했는지 알 수 있는 기준일을 표시한다. 기준일이 현재보다 7일 이상 오래되면 갱신 지연 경고와 마지막 정상 갱신 시점을 보여주는 것이 출시 요구사항이다.

기준일은 실제 현장 확인 시각이 아니다. 신고 지연, 원천 데이터 갱신 주기와 자동화 실패 때문에 현장 상황보다 늦을 수 있다.

## 계획된 가공과 검증

원본 데이터를 바로 화면에서 검색하지 않고 빌드 과정에서 정리된 정적 JSON으로 바꾼다.

- 표시용 원본 값과 검색용 정규화 값을 분리한다.
- 원본 관리번호를 우선 식별자로 사용한다.
- 필요한 필드와 출처·기준일만 남겨 파일 크기를 줄인다.
- 필수 열, 레코드 수 변화, 중복, 누락값 비율과 상태 코드 변화를 검사한다.
- JSON 구문과 출력 크기를 확인한다.
- 모든 검증을 통과한 데이터만 게시한다.

정확한 필드명, 허용값과 상태 매핑표는 아직 확정되지 않았다.

## 마지막 정상 데이터 보호

새 데이터가 검증에 실패하면 현재 배포 중인 정상 데이터를 덮어쓰지 않는다. 실패한 새 산출물보다 검증된 이전 데이터를 계속 제공하는 것이 안전하다.

이 원칙을 실제로 보장하려면 원자적 게시 방식과 실패 주입 테스트가 필요하다. 구현 방식과 테스트 결과는 M1에서 검증한 뒤 이 문서에 반영한다.

## 해석할 때 기억할 것

- `행정상 영업`과 실시간 개점 여부는 다르다.
- 검색 결과 없음은 폐업을 의미하지 않는다.
- 원본 상태, 출처와 기준일을 함께 확인한다.
- 불확실하면 시스템도 `확인되지 않음`이라고 말해야 한다.
- 중요한 방문이나 의사결정 전에는 추가 출처로 다시 확인한다.
