# 아키텍처

> 대상: 시스템이 어떻게 구성될지 이해하려는 사람
> 구현 입력: 아니오
> 기준 상태: M0 구현·기술 검증 완료 — 데이터와 제품 기능 구현 전
> 최종 검토일: 2026-08-24
> 상태: 검증된 기술 기반, 계획된 전체 구조와 미결정 사항을 구분해 설명함

## 한 문장 구조

공개 행정 데이터를 GitHub Actions에서 내려받아 검증된 정적 JSON으로 만들고, GitHub Pages의 정적 웹 애플리케이션이 이를 불러와 사용자 브라우저 안에서 검색한다.

이 전체 구조는 승인되었고 M0에서 정적 웹 애플리케이션과 테스트 기반까지 구현했다. 데이터 수집·변환·검증·게시와 실제 브라우저 검색은 아직 구현되지 않았다.

## 전체 흐름

```text
지방행정 인허가 공개데이터
  → GitHub Actions 정기 실행
  → 원천 데이터 수집과 변경 감지
  → 필드 정리·검색값 생성·상태 매핑
  → 스키마·품질·상태 코드·크기 검증
  → 검증된 정적 JSON만 게시
  → GitHub Pages가 정적 사이트와 데이터 제공
  → 브라우저가 데이터 로딩
  → 브라우저 안에서 입력 정규화와 후보 검색
  → 상태·원본 근거·출처·기준일 표시
```

사용자가 검색할 때 외부 검색 API나 런타임 데이터베이스를 호출하지 않는다.

## M0에서 구현하고 검증한 기반

- TypeScript 7.0.2와 Node.js 24.19.0 LTS를 브라우저·공유·테스트·파이프라인 코드의 공통 기반으로 선택했다.
- Preact 10.29.8과 Vite 8.2.1로 정적 웹 애플리케이션을 구성했다.
- npm 11.17.0을 사용하는 단일 저장소·단일 패키지 구조를 채택했다.
- `src/app`, `src/search`, `src/domain`, `src/pipeline`, `src/shared` 모듈 경계를 만들었다. 현재 실제 동작은 최소 화면에 한정된다.
- 정적 JSON은 JavaScript 번들 밖에 두고 브라우저가 별도로 불러오는 방향을 확정했다.
- 코드 검사, 형식 검사, 타입 검사와 정적 빌드를 하나의 빠른 검증 명령으로 실행할 수 있다.
- 단위·파이프라인·컴포넌트 테스트 구성을 만들고 데스크톱 Chromium·Firefox·WebKit과 모바일 Chromium에서 GitHub Pages 하위 경로 형태의 로컬 빌드를 검사한다.
- 데스크톱·모바일 Chromium 자동 접근성 검사 기반을 만들었다. 이는 최소 화면의 자동 검사 결과이며 최종 제품 접근성 검증을 뜻하지 않는다.

## 계획된 구성 요소

### 데이터 수집기

공식 공개데이터를 내려받고 이전 원본과 달라졌는지 확인한다. 정확한 다운로드 방식, 인증 여부, 이용조건과 출처표시 방법은 M1 전에 공식 자료를 조사해 확정한다.

### 데이터 변환기

표시용 원본 값과 검색용 정규화 값을 분리하고, 화면에 필요한 필드만 정적 JSON으로 만든다. 원본 상태 코드와 상태명은 추적할 수 있도록 보존한다.

### 검증기

필수 열, 레코드 수의 급격한 변화, 중복 식별자, 누락값, 새로운 상태 코드, 기준일, JSON 형식과 출력 크기를 검사한다. 검증에 실패한 데이터는 게시하지 않는다.

### 게시 단계

모든 검증을 통과한 산출물만 배포 대상으로 바꾼다. 실패하면 현재 서비스 중인 마지막 정상 데이터를 유지한다.

### 정적 데이터

검색과 결과 표시에 필요한 최소 정보, 원본 상태, 출처와 기준일을 포함한다. 데이터가 커지면 서울 자치구나 업종 단위로 나누어 필요한 부분만 불러올 수 있어야 한다.

### 브라우저 검색 엔진

사용자 입력을 정리하고 사업체 후보를 찾은 뒤 이름과 주소의 일치 정도를 계산한다. 주소 충돌과 낮은 신뢰도를 감지해 자동 확정을 제한한다.

### 대시보드 화면

네 가지 상태, 후보와 신뢰도, 원본 근거, 출처, 기준일, 오류와 오래된 데이터 경고를 보여준다. 키보드와 스크린리더로 전체 흐름을 사용할 수 있어야 한다.

## 경계와 책임

| 경계 | 처리 내용 | 중요한 제한 |
|---|---|---|
| 외부 데이터 경계 | 공식 공개데이터 다운로드 | 이용조건과 스키마를 먼저 확인해야 함 |
| 저장소·자동화 경계 | 수집, 변환, 검증, 산출물 생성 | 검증 실패 데이터를 게시하면 안 됨 |
| 배포 경계 | 정적 사이트와 JSON 게시 | 사람 승인과 최소 권한이 필요함 |
| 사용자 브라우저 | 입력 정리, 후보 검색, 결과 표시 | 검색어를 외부로 보내거나 HTML로 실행하면 안 됨 |
| 외부 지도 | 사용자가 직접 링크 클릭 | 자동 요청이나 페이지 수집을 하지 않음 |

## 이미 정해진 것

- 런타임 서버와 데이터베이스를 사용하지 않는다.
- 검색은 브라우저 안에서 실행한다.
- 데이터 가공은 GitHub Actions에서 수행한다.
- 정적 사이트와 데이터는 GitHub Pages로 제공한다.
- 검증 실패 시 마지막 정상 데이터를 유지한다.
- 알 수 없는 상태와 불확실한 일치는 안전하게 `확인되지 않음`으로 처리한다.
- 검색어와 사용자 행동을 수집하지 않는다.

## 아직 정하지 않은 것

- 정적 JSON의 정확한 스키마와 분할 단위
- 공식 데이터 다운로드 계약과 인증 방식
- GitHub Actions 배포 명령과 Preview·Production URL
- 마지막 정상 데이터를 원자적으로 교체하는 구체적 구현 방식

이 항목은 M1 이후의 조사·설계·승인 과정에서 결정하며, 현재 선택된 것처럼 가정하지 않는다. GitHub Pages 하위 경로 빌드는 로컬 브라우저 테스트로 검증했지만 실제 배포 워크플로와 운영 URL은 아직 없다.

## 성능과 확장 방향

첫 화면 주요 콘텐츠 2.5초, 데이터 로딩 후 검색 500ms, 압축 전 코드 번들 300KB 이하를 목표로 한다. 이는 현재 측정값이 아니라 구현 후 검증할 예산이다. 데이터가 커지면 지역 또는 업종별 분할과 지연 로딩을 사용하되, 검색 품질과 접근성을 희생하지 않는다.
