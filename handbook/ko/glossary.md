# 용어집

> 대상: 프로젝트 용어를 빠르게 확인하려는 사람  
> 구현 입력: 아니오  
> 기준 상태: Pre-M0 — 승인된 요구사항과 설계 용어 기준  
> 최종 검토일: 2026-08-18  
> 상태: 현재 문서에서 사용하는 용어를 설명함

이 용어집은 이해를 돕기 위한 설명이다. 상태 매핑이나 구현 결정을 새로 정의하지 않는다.

## 제품과 상태

| 용어 | 뜻 |
|---|---|
| 행정상 영업 | 공개 행정 데이터에 정상·영업으로 명확히 기록된 상태. 현재 시각에 문이 열려 있거나 실제 현장에서 영업 중임을 보장하지 않는다. |
| 휴업 | 공개 행정 데이터의 상태나 휴업 정보가 일시 휴업을 명확히 나타내는 경우의 화면 상태. |
| 폐업 | 원본 행정 상태가 폐업으로 명확히 분류된 경우의 화면 상태. 검색 결과가 없다는 이유만으로 사용하지 않는다. |
| 확인되지 않음 | 검색 결과 없음, 후보 충돌, 알 수 없는 상태 코드나 데이터 오류 때문에 상태를 단정할 수 없음을 나타낸다. |
| 원본 상태 | 공개데이터 제공자가 전달한 영업상태명, 상세영업상태명 또는 상태 코드. |
| 가공 상태 | 원본 상태와 승인된 매핑 규칙을 바탕으로 화면에 표시하는 네 가지 상태 중 하나. |
| 행정상 상태 | 행정기관 데이터에 기록된 상태. 실시간 개점 여부, 영업시간이나 현장 운영 상황과는 다르다. |
| 데이터 기준일 | 결과에 사용한 데이터가 어느 시점을 기준으로 하는지 나타내는 날짜. 현장 확인 시각은 아니다. |
| 오래된 데이터 경고 | 데이터 기준일이 요구된 최신성 범위를 벗어났음을 알리는 표시. |

## 검색

| 용어 | 뜻 |
|---|---|
| 정규화 | 원본 표시값은 보존하면서 공백, 구두점과 주소 요소를 비교 가능한 검색값으로 정리하는 과정. |
| 후보 | 입력한 상호명이나 주소와 관련이 있을 가능성이 있어 검색 결과로 검토하는 사업체 레코드. |
| 후보 순위 | 이름과 주소의 일치 정도에 따라 후보를 정렬한 순서. |
| 신뢰도 | 후보가 입력과 얼마나 잘 맞는지 설명하는 수준. 사업체의 영업 상태를 의미하지 않는다. |
| 주소 충돌 | 이름은 같지만 주소가 명백히 달라 동일 사업체로 자동 확정할 수 없는 상황. |
| 유사 후보 | 근거가 충분하지 않아 자동 확정하지 않고 사용자가 직접 비교하도록 보여주는 후보. |
| Top-3 재현율 | 정확한 이름과 주소를 입력했을 때 대상 사업체가 상위 세 후보에 포함되는 비율. v1.0 목표는 90% 이상이다. |

## 시스템과 데이터

| 용어 | 뜻 |
|---|---|
| 정적 사이트 | 요청 때마다 서버가 화면을 만드는 대신 미리 생성된 HTML, CSS, JavaScript와 데이터 파일을 제공하는 웹사이트. |
| 정적 JSON | 빌드 과정에서 검증해 만들어 두고 브라우저가 내려받는 데이터 파일. |
| 브라우저 검색 | 사용자의 기기 안에서 정적 데이터를 검색하는 방식. 검색어를 별도 검색 서버로 보내지 않는다. |
| ETL | 데이터를 추출하고 변환한 뒤 사용할 형태로 적재하는 과정. 이 프로젝트에서는 GitHub Actions가 빌드 시 수행할 예정이다. |
| GitHub Actions | 데이터 수집·변환·검증과 정적 빌드를 자동 실행할 예정인 GitHub 자동화 기능. |
| GitHub Pages | 정적 웹사이트와 JSON을 제공할 기본 호스팅 대상. |
| 마지막 정상 데이터 | 모든 검증을 통과해 현재 제공 중인 가장 최근 데이터. 새 갱신이 실패하면 이를 보존한다. |
| 원자적 게시 | 검증된 산출물 전체를 완성된 한 단위로 교체해 일부만 게시되는 상태를 피하는 방식. 구체적 구현은 아직 미정이다. |
| 데이터 분할 | 큰 정적 데이터를 지역이나 업종 등 여러 파일로 나누어 필요한 부분만 불러오는 방식. |

## 프로젝트 운영

| 용어 | 뜻 |
|---|---|
| PRD | 제품 목적, 범위, 요구사항과 출시 기준을 기록한 제품 요구사항 문서. |
| ADR | 중요한 기술·제품 결정을 배경, 선택, 이유와 결과와 함께 기록한 문서. |
| 마일스톤 | 관련 작업과 검증을 묶은 프로젝트 단계. M0는 기술 기반, M1은 데이터, M2는 검색·화면, M3는 출시 품질을 다룬다. |
| 개발 하네스 | AI 역할, 작업, 기억, 승인과 검증 절차를 관리하는 영어 문서 체계. |
| 사람용 핸드북 | 프로젝트를 이해하려는 사람을 위한 이 한국어 문서 모음. 구현 입력이나 정본이 아니다. |
| Pre-M0 | 기술 스택과 저장소 기반을 결정하는 M0를 시작하기 전의 현재 상태. |
| 사람 승인 | AI나 자동화가 단독으로 결정하거나 실행하지 않고 책임 있는 사람이 확인해야 하는 단계. |

## 가장 중요한 구분

- `행정상 영업` ≠ 현재 문이 열려 있음
- 검색 결과 없음 ≠ 폐업
- 검색 신뢰도 ≠ 행정상 상태
- 데이터 기준일 ≠ 현장 확인 시각
- 사람용 핸드북 ≠ 구현 명세
