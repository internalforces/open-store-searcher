# 프로젝트 개요

> 대상: 프로젝트의 목적과 범위를 이해하려는 사람
> 구현 입력: 아니오
> 기준 상태: M0 구현·기술 검증 완료 — 제품 기능 구현 전
> 최종 검토일: 2026-08-24
> 상태: 승인된 제품 요구사항과 검증된 기술 기반을 설명하며 실제 검색 제품은 아직 구현되지 않음

## 무엇을 만드는가

`open-store-searcher`는 상호명이나 주소로 서울 소재 인허가 사업체를 검색하고, 공개 행정 데이터에 기록된 상태와 그 근거를 보여주는 무료 오픈소스 정적 대시보드다.

사용자가 결과를 보면서 다음 질문에 답할 수 있게 하는 것이 목적이다.

- 어떤 사업체 후보가 입력한 이름과 주소에 가장 잘 맞는가?
- 공개 행정 데이터에는 어떤 상태로 기록되어 있는가?
- 그 판단에 사용한 원본 상태와 데이터 출처는 무엇인가?
- 데이터는 어느 시점을 기준으로 하는가?
- 결과가 불확실할 때 무엇을 추가로 확인해야 하는가?

## 왜 필요한가

지도 검색이나 일반 검색만으로 사업체 상태를 판단하면 동명이점, 이전 사업장, 상호 변경과 검색 누락을 혼동할 수 있다. 검색 결과가 없다는 이유만으로 폐업을 단정하는 것도 위험하다.

이 프로젝트는 지도 페이지를 자동 수집하거나 유료 API에 의존하지 않는다. 공개 인허가 데이터를 정기적으로 가공하고, 출처·기준일·불확실성을 함께 제시해 사람이 근거를 확인할 수 있게 한다.

## 주요 사용자

- 주소 목록을 정리하거나 현장 방문을 준비하는 개인
- 소상공인·점포 데이터를 검토하는 연구자와 시민 개발자
- 공공데이터를 활용한 오픈소스 사례를 살펴보는 기여자

## 계획된 사용 흐름

아래 흐름은 승인된 요구사항이며 아직 구현되지 않았다.

1. 사용자가 상호명, 주소 또는 두 정보를 함께 입력한다.
2. 브라우저가 입력을 정리하고 정적 데이터에서 후보를 찾는다.
3. 상호명과 주소의 일치 정도에 따라 후보 순서를 정한다.
4. 주소가 충돌하거나 근거가 약하면 자동 확정하지 않고 유사 후보로 보여준다.
5. 선택한 결과에 행정상 상태, 원본 상태, 주소, 업종, 날짜, 출처와 데이터 기준일을 함께 표시한다.
6. 필요하면 사용자가 직접 네이버 지도나 카카오맵 검색 링크를 열어 추가 확인한다.

검색어는 브라우저 안에서 처리하며 서버로 전송하거나 저장하지 않는 것이 핵심 원칙이다.

## 제품 원칙

### 근거를 함께 보여준다

가공된 상태만 제시하지 않는다. 원본 상태, 출처와 데이터 기준일을 함께 보여줘 사용자가 판단 근거를 확인할 수 있게 한다.

### 불확실하면 단정하지 않는다

검색 결과 없음, 주소 충돌, 새로운 상태 코드나 데이터 오류가 있으면 `확인되지 않음`으로 처리한다. 불확실성을 숨기는 것보다 추가 확인을 요청하는 편을 택한다.

### 실제 개점 여부와 행정상 상태를 구분한다

`행정상 영업`은 현재 시각에 문이 열려 있다는 뜻이 아니다. 영업시간, 휴무일, 임시휴무나 현장 상황은 이 프로젝트가 판정하지 않는다.

### 기본 운영 비용을 0원으로 유지한다

서버나 런타임 데이터베이스 없이 GitHub Pages와 GitHub Actions를 사용한다. 결제수단이 필요한 서비스, 유료 API와 상시 서버는 기본 구조에 포함하지 않는다.

### 사용자를 추적하지 않는다

검색어, 클릭, 위치와 사용 행동을 수집하지 않는다. 분석·광고·추적 스크립트를 넣지 않는다.

## 초기 범위

- 지역: 서울특별시
- 대상: 지방행정 인허가 공개데이터에 포함되는 업종과 사업장
- 검색 입력: 상호명, 주소 또는 두 정보의 조합
- 표시 상태: `행정상 영업`, `휴업`, `폐업`, `확인되지 않음`
- 배포 형태: GitHub Pages 정적 사이트
- 코드 라이선스: MIT

서울 이외 지역은 서울 데이터의 품질과 성능을 검증한 뒤 별도 정적 파일로 확장하는 P1 범위다.

## 제공하지 않는 것

- 실시간 `영업 중`, `영업 종료`, 브레이크타임 판정
- 영업시간, 휴무일과 임시휴무 정보
- 지도·검색 페이지의 자동 수집
- 유료 지도·장소 API
- 내장 지도, 리뷰, 별점과 사진
- 회원가입, 로그인과 사용자별 검색 기록
- 서버, 런타임 데이터베이스와 관리자 화면
- AI를 이용한 상태 판정
- 공개데이터에 없는 모든 일반 사업체의 포괄적 검색
- 분석, 광고와 사용자 추적

## 성공 기준

최종 v1.0에서는 사용자가 30초 안에 사업체 후보, 행정상 상태, 근거와 기준일을 확인하고 필요한 추가 검증으로 이동할 수 있어야 한다. 정확한 이름과 주소로 구성한 검증 세트에서는 대상 사업체의 90% 이상이 상위 세 후보 안에 포함되는 것을 목표로 한다.

이 수치는 아직 달성된 결과가 아니라 출시 전에 검증해야 하는 기준이다.

## 현재 상태와 다음 단계

M0에서 TypeScript와 Node.js, Preact와 Vite, npm, 단일 저장소·단일 패키지 구조를 승인하고 최소 정적 애플리케이션과 개발·빌드·검증 기반을 구성했다. 프로젝트 소스 코드는 MIT로 배포하고 각 의존성은 해당 라이선스 조건에 따라 관리한다. 단위·파이프라인·컴포넌트 테스트 구조와 데스크톱·모바일 브라우저 검사, 자동 접근성 검사 기반도 검증했다.

다만 지금 화면은 기반 확인용 최소 화면일 뿐 사업체 검색 제품이 아니다. 다음 단계인 M1의 TASK-004에서 공식 원천 데이터의 다운로드 방식, 스키마, 이용조건과 출처표시 요구사항을 확인해야 한다. 그 전에는 데이터 필드나 상태 매핑을 구현 사실처럼 가정하지 않는다.
