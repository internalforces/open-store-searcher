# 검색과 화면

> 대상: 사용자가 어떻게 검색하고 결과를 확인하게 될지 이해하려는 사람  
> 구현 입력: 아니오  
> 기준 상태: Pre-M0 — 검색과 화면은 요구사항만 승인됨  
> 최종 검토일: 2026-08-18  
> 상태: 계획된 사용자 경험을 설명하며 실제 기능은 아직 없음

## 현재 구현 상태

검색창, 검색 알고리즘, 결과 카드와 접근성 동작은 아직 구현되지 않았다. 이 문서는 승인된 제품 요구사항과 안전 원칙을 설명하며, 실제 동작과 성능은 M2와 M3에서 구현·검증한 뒤 갱신한다.

## 계획된 검색 입력

하나의 검색 영역에서 다음 입력을 허용할 계획이다.

- 상호명만 입력
- 주소만 입력
- 상호명과 주소를 함께 입력

앞뒤 공백과 연속 공백을 정리한다. 빈 검색어와 한 글자 검색어는 실행하지 않고 더 구체적인 입력을 요청한다.

입력값은 브라우저 안에서 텍스트로만 처리한다. HTML로 실행하지 않으며 검색어를 서버, 분석 도구나 외부 검색 서비스로 자동 전송하지 않는다.

## 입력을 비교 가능한 형태로 정리하는 방법

표시용 원본 값은 그대로 보존하면서 검색용 값만 별도로 정리한다.

- 상호명: 공백, 일반적인 구두점과 HTML 표기를 정리한다.
- 주소: 시·구·동, 도로명과 건물번호처럼 비교에 필요한 요소로 나눈다.
- 건물번호에 필요한 숫자와 하이픈은 보존한다.
- 도로명주소와 지번주소를 모두 활용할 수 있게 한다.

세부 정규화 규칙은 테스트 사례와 함께 구현해야 하며 현재 확정된 코드나 라이브러리는 없다.

## 후보 순서의 기본 원칙

후보는 대체로 다음 순서로 높은 관련성을 갖는다.

1. 상호명과 주소가 모두 정확히 일치
2. 상호명이 정확히 일치하고 구·동 또는 도로명·건물번호가 일치
3. 상호명이 일부 일치하고 주소의 핵심 요소가 일치
4. 주소가 정확히 일치하고 상호명이 유사
5. 상호명 또는 주소만 일부 일치

이 순서는 요구사항 수준의 원칙이다. 실제 점수와 동점 처리 규칙은 검색 품질 테스트를 만들면서 확정한다.

## 자동 확정을 제한하는 경우

이름이 같더라도 주소가 분명히 다르면 같은 사업체로 자동 확정하지 않는다. 주소가 불완전하거나 이름만 일치하는 경우에도 신뢰도가 낮은 유사 후보로 보여줘 사용자가 선택하게 한다.

계획된 신뢰도 표현은 다음과 같다.

- 높음: 이름과 주소가 모두 명확히 일치
- 보통: 일부 정보가 빠졌지만 동일 사업체로 볼 근거가 충분함
- 낮음: 이름만 같거나 주소가 불완전해 사람의 확인이 필요함

신뢰도는 행정상 상태와 다른 개념이다. 신뢰도는 검색 후보가 입력과 얼마나 잘 맞는지를 설명하며, 사업체가 영업 중인지 판단하는 값이 아니다.

## 결과에서 보여줄 정보

계획된 결과 카드는 다음 내용을 함께 표시한다.

- 사업장명과 주소
- 업종 또는 업태
- 네 가지 화면 상태 중 하나
- 검색 후보 신뢰도
- 원본 영업상태와 상세영업상태
- 제공되는 인허가·휴업·재개업·폐업·수정 날짜
- 원본 데이터 출처와 데이터 기준일
- 추가 확인을 위한 외부 지도 검색 링크

상태는 색상만으로 구분하지 않고 반드시 텍스트를 함께 사용한다.

## 결과가 없을 때

기본 안내 문구는 다음 의미를 유지해야 한다.

> 일치하는 공개 인허가 데이터를 찾지 못했습니다. 데이터 미등재, 상호 변경 또는 검색어 차이일 수 있으며 폐업을 의미하지 않습니다.

빈 결과는 오류가 아닐 수 있으며 `폐업`으로 바꾸어 표시하지 않는다.

## 오류와 오래된 데이터

- 데이터 파일을 불러오지 못하면 새로고침 방법과 저장소 이슈 제보 경로를 안내한다.
- 데이터 기준일이 오래되면 마지막 정상 갱신일과 경고를 표시한다.
- 잘못된 레코드가 있으면 해당 레코드를 제외하되 가능한 검색은 계속 제공한다.

정확한 오류 화면과 복구 동작은 구현 후 테스트해야 한다.

## 접근성

최종 화면은 모바일과 데스크톱에서 사용할 수 있어야 하며, 키보드만으로 입력·후보 탐색·결과 선택·외부 링크 이동을 수행할 수 있어야 한다. 입력, 결과 목록과 오류 메시지는 스크린리더가 이해할 수 있는 이름과 상태 알림을 제공해야 한다.

기준은 WCAG 2.1 AA의 기본 요구사항이며, 자동 검사뿐 아니라 키보드와 스크린리더를 이용한 수동 검토가 필요하다.

## 외부 지도 링크

네이버 지도와 카카오맵의 검색 URL을 안전하게 만들어 사용자가 직접 열 수 있게 할 계획이다. 프로젝트가 지도 페이지를 자동으로 요청하거나 수집하지는 않는다. 외부 링크를 새 창으로 열 때는 안전한 링크 정책과 올바른 URL 인코딩을 적용해야 한다.
