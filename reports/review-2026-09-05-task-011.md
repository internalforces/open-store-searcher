## Strengths

- The implementation is a pure, browser-compatible transformation with no I/O, storage, network,
  logging, HTML parser, or new dependency.
- It retains the exact original input, keeps the TASK-006 V1 NFKC/lowercase/Unicode-whitespace
  baseline in `normalizeSearchText`, and treats notation as text rather than rendering it.
- `projectSearchText` is now a reusable, no-validation field projection, so candidates and valid
  user queries derive exactly the same fields while minimum-length guidance remains query-only.
- The tests exercise names, addresses, combined input, Unicode grapheme boundaries, whitespace,
  case-insensitive bounded notation, punctuation-only input, and ASCII and Unicode-dash building
  numbers.

## Findings

### Resolved — candidate-field projection was coupled to user-query validation

`projectSearchText` at `src/search/prepare-search-query.ts:39-58` now returns projections for
empty and one-grapheme candidate fields without applying user-input guidance. `prepareSearchQuery`
uses that projection and applies the two-grapheme rule only afterward. The regression at
`src/search/prepare-search-query.test.ts:9-25` proves that a one-grapheme candidate remains
projectable while a corresponding one-grapheme query is rejected. This resolves the FR-01 and PRD
9.2 issue.

### Resolved — non-ASCII dash punctuation was dropped from address numbers

`projectSearchText` canonicalizes Unicode dash punctuation to ASCII `-` before the remaining
punctuation treatment at `src/search/prepare-search-query.ts:47-51`. The regression at
`src/search/prepare-search-query.test.ts:27-35` covers ASCII, U+2010, U+2011, U+2013, and
full-width hyphen forms, each retaining a single hyphenated number token. This resolves the PRD
9.2 address-token requirement.

### Resolved — uppercase common notation

The bounded named/numeric matcher at `src/search/prepare-search-query.ts:21-29` is now
case-insensitive and normalizes the matched body before entity lookup and hexadecimal detection.
The regression at `src/search/prepare-search-query.test.ts:92-94` proves uppercase named and
numeric hexadecimal notation projects identically to its decoded inert-text equivalent. The
normalization remains bounded and does not parse or execute HTML.

## Verdict

**Approved.** The two Important findings are resolved with focused, meaningful regressions. The
module meets the TASK-011 input-normalization scope, preserves the V1 baseline and originals,
keeps browser processing local and inert, and deliberately leaves ranking and UI integration to
their assigned later tasks.
