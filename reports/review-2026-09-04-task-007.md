# TASK-007 Independent Review

Date: 2026-09-04

Verdict: **Approved**

## Scope and Findings

Reviewed accepted ADR-013, the TASK-007 design and active acceptance criteria, recorded official
source evidence, the domain mapper and its tests, transformer changes and regressions, and the
exact-file coverage configuration. No material correctness or test-quality findings remain.
The review excludes unrelated pre-existing worktree changes and `handbook/ko/**`.

The three exact approved aggregate pairs are the only branches returning a verified status.
All other typed inputs return the unverified status, including the mixed aggregate `04` bucket.
The mapper does not normalize text or read detailed fields. The transformer retains all four raw
fields and adds processed status to schema V2. Identity and normalization contracts remain V1;
source references contain no stale V1 transformer consumers. No new dependency, deployment,
production-data operation, collection behavior, or freshness derivation is introduced.

## Requirement and Assertion Evidence

| Requirement | Evidence |
|---|---|
| FR-04: exact four-status contract | `maps the approved pair %s / %s` asserts literal expected statuses independently of production logic. |
| FR-07: missing, contradictory, and unknown inputs fail safely | `fails safely for aggregate combination %j / %j` covers the cross-product of null, empty, known, unknown, and object-property-like strings. |
| FR-07: exact spelling and Unicode boundaries | `rejects whitespace and Unicode variants of %s / %s` tests both ends of both fields, fullwidth digits, and decomposed names; the detailed-evidence test also rejects the fullwidth slash. |
| Detailed evidence must not affect classification | `does not read or mutate detailed evidence` uses frozen inputs and throwing getters; `preserves raw evidence while mapping %s / %s` combines each aggregate case with null, operating, closed, and unknown detailed evidence. |
| Raw evidence must survive transformation and serialization | `preserves raw evidence while mapping %s / %s` compares all four raw fields, verifies source input remains unchanged, and checks serialized evidence and status. |
| Schema V2 without identity, normalization, or ordering changes | `versions processed output without changing identity, normalization, or ordering` verifies version literals, identity, search, display, provenance, diagnostics, and deterministic serialization. |
| Missing results must not imply closure | `does not infer a status for an empty stage` asserts the complete empty V2 output. |
| Section 12.2: exact mapper coverage gate | `vitest.config.ts` requires 100% statements, branches, functions, and lines for `src/domain/map-license-status.ts` while preserving global gates. |
| Synthetic and offline boundaries | Colocated fixtures are explicitly synthetic; integration inputs use only the accepted schema contract, with no production records or network fixture dependency. |

Assertions test externally visible results rather than copying the mapper implementation. The
integration cases exercise aggregate and detailed contradictions together. Existing transformer
regressions remain in place with only the expected schema/API and processed-status adaptations.
