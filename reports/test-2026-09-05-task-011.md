# TASK-011 input validation and normalization

Date: 2026-09-05. Scope: FR-01/02, PRD 9.1/9.2; browser-only pure input preparation.

## Contract

One unclassified input produces both name and address comparison keys and address tokens.
Original text is preserved exactly. The baseline duplicates the accepted TASK-006 V1 algorithm
without importing the Node crypto-dependent pipeline module or changing source normalization.
NFKC, lowercase and Unicode White_Space cleanup precede comparison. Only search keys change.

Common case-insensitive semicolon-terminated amp/lt/gt/quot/apos/nbsp and bounded decimal/hex numeric notation
are decoded once as strings; unsupported or invalid references are retained. No HTML parser,
DOM, I/O, storage, logging or dependency is introduced. Punctuation becomes name separators.
Unicode dash punctuation is canonicalized to ASCII hyphen. Other address punctuation becomes separators, and letter/digit transitions split
into tokens without losing number, district, road, floor or unit text. No alias expansion,
address/name split inference, identity merge or ranking occurs.

`projectSearchText` also projects empty or single-character candidate fields without applying query validation.

Minimum length counts grapheme clusters in the punctuation-cleaned name view excluding spaces.
Zero and one return typed rejection plus Korean guidance. This rule applies after normalization.
The two projections describe comparison inputs, not proof of a match. TASK-012 must normalize
candidate text consistently and handle uncertainty. Product input rendering and guidance wiring
remain TASK-014/015; this does not complete FR-01/02 end to end or close M2.
