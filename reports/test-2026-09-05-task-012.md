# TASK-012 candidate search verification — 2026-09-05

Result: PASS. Accepted design implemented; independent Reviewer Approved in

## Implementation

`compare-search-address.ts` parses address components and compares same-family evidence.
`interpret-search-query.ts` interprets contiguous query spans once without candidate-dependent
splitting. `search-candidates.ts` builds a transient validated index, preserves typed original
record references, applies ordinal evidence tiers and conflict/ambiguity vetoes, and returns
high/medium Top-3 separately from all low-confidence candidates. Stable identifier tie-breaking
does not create certainty: equal-strength high matches have no primaryMatch. Invalid records and
entire duplicate-ID groups are excluded with aggregate diagnostics. No status is inferred.

The source TASK-011 projection and accepted source/status contracts are unchanged. Browser work
uses no new dependency. Public artifact loading/schema and UI are not introduced here.

## Requirement and assertion matrix

All engine test names below are in `src/search/search-candidates.test.ts` unless specified.

| ID | Requirement | Exact test evidence |
|---|---|---|
| S01 | Reuse normalization and preserve originals; reject invalid input without scanning | `S01 reuses query normalization, preserves original records, and rejects invalid input` uses a throwing entries Proxy for invalid input; `preserves source and status types on original record references` checks compile-time types and original identity |
| S02 | Mixed query interpretation and ambiguity | `S02 interprets name-first, address-first, address-only, and ambiguous address spans`; address suite `extracts name-first and address-first spans with attached road numbers`; `keeps no-address names and flags weak, split, repeated and unsupported address interpretations` |
| S03 | Exact-first and bounded partial matching | `S03 ranks exact and core evidence ahead of partial and name-only candidates`; `S03 retrieves literal partial address text without treating numeric prefixes as matches` |
| S04 | Same-name address-conflict veto | `S04 keeps conflicting district, road, locality, and number evidence out of Top-3 and primary` |
| S05 | Number/hyphen boundaries and missing evidence | `S05 compares complete numeric tokens, Unicode hyphens, and missing numbers conservatively`; address suite `compares complete number tokens %s versus %s` includes 12/120, 12-1/121, 12/012 and 12-1/12-2; `distinguishes missing numbers from contradictory numbers and canonicalizes Unicode dashes` |
| S06 | Address family isolation and contradictory alternate evidence | `S06 keeps road and parcel comparison independent and does not union fields`; address suite `does not compare road building numbers against parcel lot numbers` |
| S07 | High/medium/low and status preservation | `S07 separates high, medium, and low confidence without mutating status data`; S01 also proves a unique name-only match remains low; S02 tests absent-name address-only medium and one-grapheme partial-name rejection |
| S08 | Top-3, counts, no padding, deterministic ties | `S08 returns deterministic Top-3 counts, keeps low matches separate, and suppresses tied primary matches` checks eligible counts 0/1/2/3/4 and reversed input |
| S09 | Invalid records and duplicate groups | `S09 excludes malformed records and duplicate-ID groups without merging distinct records` |
| S10 | Actual browser engine and no query I/O | `runs the bundled candidate engine without browser query I/O` in `tests/e2e/search.spec.ts`, executed in Chromium, Firefox, WebKit and mobile Chromium |

The S10 test bundles the actual engine in memory with Vite, verifies no external imports and no
Node module dependency, then injects it into the locally served Pages-subpath shell. Network,
storage and logging instrumentation surrounds both index creation and search. Sentinel self-checks
prove that fetch, inherited sendBeacon, both storage receivers and console calls are observable;
probe counters are cleared before engine work and descriptors restored afterward. The test also
checks normalized exact evidence, a same-name conflicting address, unique name-only uncertainty,
tied high results and invalid empty input. It performs no external provider retrieval.
